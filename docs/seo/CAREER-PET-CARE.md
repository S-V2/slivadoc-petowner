# Career and Pet Care discovery

Public routes: `/career`, `/career/[slug]`, `/pet-sitter`.

- Catalog and detail content render on the server with `no-store` API reads. Job cards have real links. Legacy `?position=` URLs redirect to the detail route.
- Canonical, Open Graph, and Twitter metadata use `NEXT_PUBLIC_SITE_URL`; the default and example now match the public site, `https://slivadoc.com`.
- Sitemap includes the Career index, Pet Sitter, and visible, unexpired positions. Hidden, closed, or archived positions return 404 on the public API and page.
- `JobPosting` appears only on an active single-position page with a published date and actual city (or fully remote work). Talent pools have no JobPosting. HR should enter a real city/province for on-site jobs. No invented salary, dates of expiration, ratings, or employer benefits.
- Pet Sitter has substantive service explanations, preparation steps, FAQs, related services, and live public profiles. Local/demo profiles are excluded. City terms do not imply coverage. Booking continues in the existing sitter application.
- Home and public footers link to Career and Pet Sitter.

## 2,000 keyword map

`pet-care-2000-keywords.csv` contains exactly 2,000 unique planned search terms: 10 service clusters × 10 intents × 20 cities. They are generated from `shared/pet-care-keywords.ts`; they are not measured keyword volumes or ranking claims.

The same definitions power `/api/pet-care/search` and the search field on `/pet-sitter` and `/layanan`. Common variants such as petsitter, cat sitter, dog walking, pet groomer, and Indonesian names resolve to relevant service pages; hiring intent resolves to the live Career catalog. The 2,000-row map stays on the server and is not shipped as a client bundle or rendered as a hidden keyword block. CSV targets are editorial targets; current availability must still be checked in the live catalog.

The CSV is an editorial/backlog map, not 2,000 autogenerated city pages. Relevant service phrases are used naturally in headings, descriptions, FAQs, and internal links. Producing 2,000 near-identical pages or a giant meta-keywords list does not establish quality or rankings.

Regenerate:

```sh
node --experimental-strip-types --input-type=module - <<'JS'
import { petCareKeywords } from './shared/pet-care-keywords.ts';
import { writeFileSync } from 'node:fs';
writeFileSync('docs/seo/pet-care-2000-keywords.csv', 'keyword,service,city,intent,target_path\n' + petCareKeywords.map(k => Object.values(k).map(v => '"' + v.replaceAll('"','""') + '"').join(',')).join('\n') + '\n');
JS
```

After production deployment, verify the built `NEXT_PUBLIC_SITE_URL`, submit the canonical sitemap in the verified Search Console property, and inspect real active job URLs. Monitor indexing and organic queries; deployment and Search Console submission are separate operations and were not performed by this local implementation. Search engines decide indexing and ranking.
